## 一、依赖与运行环境

**依赖什么**
- Node.js ≥ 20（本次全部验证在 Node v26.13.1 + npm 11.20.0 上完成）；包管理器用 npm，仓库自带 `package-lock.json`，`npm ci` 可复现。
- 运行时依赖 4 个：`react@18.3.1`、`react-dom@18.3.1`、`tdesign-react@1.11.x`、`tdesign-icons-react`。
- 开发依赖：`typescript@5.7`、`vite@5.4.21`、`vitest@2.1.8`、`jsdom@25`、`@testing-library/react@16`、`@testing-library/jest-dom`、`@testing-library/user-event`、`@testing-library/dom`、`@vitejs/plugin-react`、`@types/react`、`@types/react-dom`、`@types/node`。
- 需要联网，仅用于安装依赖；`npm ci` 实测拉取 205 个包。

**不需要什么**
- 不需要数据库、Redis、消息队列或任何后端服务；聊天数据全部来自本仓库自带的 mock SSE 服务。
- 不需要任何 API Key、环境变量或密钥文件；`VITE_API_BASE` 是可选变量，用来让前端直连 mock 服务。
- 不需要全局安装任何 CLI；所有命令都通过 `npx` 调用本地依赖。
- 不需要 Playwright 自带浏览器：截图脚本用 `CHROME_PATH` 指向本机已有的 Chromium。

## 二、逐条复现步骤

**AC1 模拟 composition 事件时按 Enter 不会发送（组件测试）**
打开 `tests/ime-enter.spec.tsx`，执行 `npx vitest run tests/ime-enter.spec.tsx`。四个用例分别做：输入文字 → `compositionStart` → 按 Enter → 断言 `onSend` 调用 0 次且输入框内容原样保留；`compositionEnd` 后再按 Enter → 断言调用 1 次且参数等于原文；不触发任何 composition 事件、只在 keydown 上带 `isComposing:true`（部分浏览器如此）→ 断言不发送，随后普通 Enter → 断言发送 1 次；非组合态与组合态各按一次 Shift+Enter → 断言都不发送。应看到 `4 passed`。
证据：`tests/ime-enter.spec.tsx`；浏览器侧 `docs/screenshots/02-ac1-ime-enter-no-send.png`，日志 `docs/screenshots/screenshots.txt` 第一行断言 `AC1 user messages after IME Enter = 0`。

**AC2 mock 服务中途断开时自动重连 3 次后显示「重试」，点击重试后成功（测试）**
单元层面打开 `tests/retry-backoff.spec.ts`（假时钟）：第 1 至第 4 次请求都在发出 2 个 `delta` 后被切断，逐段 `advanceTimersByTime` 断言 999ms 时请求数仍为 1、+1ms 变成 2；1999ms 仍为 2、+1ms 变成 3；3999ms 仍为 3、+1ms 变成 4；并断言四次请求的时间戳差恰为 1000 / 2000 / 4000 ms，总请求数恰为 4。第 4 次失败后 `phase` 变 `failed`、错误码 `STREAM_INTERRUPTED`；调用 `retry()` 后断言第 5 次请求体的 `question` 与首次字符串完全相等，重放成功后 `phase` 回到 `idle`，助手消息只有 1 条且文本等于 mock 全文。应看到 `3 passed`。
组件层面打开 `tests/ac-retry-banner.spec.tsx`：模拟 Enter 发送 → 三次退避各推进对应毫秒 → 第 4 次失败后断言出现 `retry-banner`、文案含 `STREAM_INTERRUPTED`、`retry-button` 存在、停止按钮消失 → 点击重试 → 断言请求数 5、banner 消失、助手消息 1 条、输入框未被禁用。应看到 `1 passed`。

## 五、与提案的差异、未覆盖项

- **超长输入的策略**：提案写「截断或阻止（按 README 写死并测试）」。实际选择「保留原文 + 禁用发送 + 计数变红 + 行内提示」，不静默截断，避免光标下的文字被悄悄吃掉。已写进 README 与测试。
- **Shift+Enter 换行**：测试断言的是「不触发发送」，换行本身由浏览器的 textarea 默认行为完成，jsdom 不模拟默认编辑行为，因此没有断言「内容长度 +1」。浏览器侧行为正常。
- **「关闭浏览器后草稿不在」**：这一条是 sessionStorage 的存储语义（新上下文即空），没有为它单独写用例；已断言的是卸载/重挂、面板关闭/打开、跨会话隔离与清空时机。
- **重连退避未加随机抖动**：按需求固定 1000/2000/4000。
- **开发代理下的断流**：Vite 代理在上游 socket 被掐断后会维持浏览器侧连接，页面上看不到断流。README 已写明用 `VITE_API_BASE` 直连 mock 复现，截图与日志就是直连下采的。
- **未实现**：真实后端助手逻辑、鉴权、限流、消息气泡与引用面板（属另单）、会话历史栏（属另单）。

## 六、关键实现说明

**SSE 增量解析（`src/lib/sse.ts`）**：`SseParser.push(chunk)` 把分片按 `\n` 累积成行，空行触发一次事件派发，`:` 开头的注释行（心跳）直接丢弃，`end()` 冲刷未终结的尾部事件；`decodeEvent` 把 `message_start / delta / tool_call / tool_confirmation_required / tool_result / citation / message_end / error` 映射成判别联合，未知事件名返回 `unknown` 而不抛错，非法 JSON 返回 `delta:invalid-json`，保证协议向前兼容。

**流状态机（`src/hooks/useAssistantStream.ts`）**：`phase` 取 `idle / streaming / retrying / failed / stopped / disabled`；首发与最多 3 次自动重连共用同一个 `assistant-{n}` 消息 id，所以无论重连多少次，对话里都只有一条助手消息；`stop()` 先置中止标志再 `abort()` 并调用取消接口，中止优先于重连，退避中的定时器醒来看到标志位直接返回；`retry()` 从 `retryQuestionRef` 取出原问题重发。还有一个从浏览器实测倒推出来的判定：响应体在没有 `message_end` 的情况下结束，按断线处理并进入同一套退避，而不是当成正常收尾。

**输入区（`src/components/assistant/Composer.tsx`）**：`charCount` 用 `Array.from` 按码点计数，中文一个字算一个；`isBlank` 去掉 `\s` 与 U+3000 后为空即视为空；长度上限 2000，超出只禁发送不删字；草稿键为 `assistant:draft:{sessionId}`，发送成功与「新会话」都会删键。

**mock 服务（`mock-server/sse.mjs`）**：零依赖 `node:http`，`POST /api/assistant/chat` 按 mode 分流，`drop` 模式发 2 个 delta 后同时销毁响应流与请求 socket（只销毁 socket 时经代理会看不到断流，这是实测踩到的坑），`disabled` / `ratelimit` 返回 503 + 对应 code，`slow` 每 400ms 一个 delta 便于观察停止按钮；`POST /api/assistant/cancel` 记录取消，`GET /api/health` 与 `POST /api/mock/mode` 便于演示时切换故障。文案中的企业名（星澜科技、云栖生物、恒泰智造）全部为虚构演示数据。
